## Step 6: USB TX ring buffer

**Problem:** `CDC_Transmit_FS` returns `USBD_BUSY` while a transfer is in flight. When several messages were sent close together, every message after the first was dropped.

**What a "burst" means:** many messages written back to back with no pause, faster than USB can send them one at a time. For example, 100 lines of 32 bytes each (3.2 KB) can be queued in well under a millisecond. With the old code, only `burst 000` arrived. The same thing happens with sensor data, such as an IMU at 1 kHz plus fusion output plus debug lines.

### Design

```
main loop                         tx_ring[4096]                  USB interrupt
usb_printf ─► usb_write ─► [ tail ..in-flight.. | ..queued.. head ]
                  │                   ▲                     │
                  └─ kick (IRQ masked)┘   TransmitCplt ─► tail += inflight; kick next chunk
```

- **Free-running indices:** `head` and `tail` are `uint32_t` counters that only count up. `used = head - tail` stays correct even when they wrap. The size is a power of 2, so `& MASK` gives the position in the buffer.
- **One writer per index:** only `usb_write` (main loop) moves `head`. Only `TransmitCplt` (USB interrupt) moves `tail`.
- **`tail` moves only after a transfer completes,** because the USB core reads straight from `tx_ring` while the transfer is in flight.
- **A kick sends one contiguous chunk** of up to 1024 bytes, which stops at the end of the buffer. The next kick continues from the start. The CDC library sends the ZLP itself when a chunk is a multiple of 64 bytes (`usbd_cdc.c:549`).
- **Never blocks:** if a message does not fit, the whole message is dropped and counted (all-or-nothing).
- No D-cache steps are needed: USB FS uses `dma_enable = DISABLE`, and the D-cache is off.

### Code: `USB_DEVICE/App/usbd_cdc_if.c`

`/* USER CODE BEGIN PRIVATE_VARIABLES */` (the `usb_rx_*` lines stay):
```c
#define USB_TX_RING_SIZE  4096u                 /* must be power of 2 */
#define USB_TX_RING_MASK  (USB_TX_RING_SIZE - 1u)
#define USB_TX_CHUNK_MAX  1024u                 /* max bytes per USB transfer */
static volatile uint8_t  usb_rx_buf[64];
```

```c
/* Start next transfer. Call only from USB IRQ, or with OTG_FS_IRQn masked. */
static void usb_tx_kick(void)
{
  if (tx_inflight != 0) return;                                   /* busy */
  if (hUsbDeviceFS.dev_state != USBD_STATE_CONFIGURED) return;    /* no host */

  uint32_t used = tx_head - tx_tail;
  if (used == 0) return;                                          /* empty */

  uint32_t idx   = tx_tail & USB_TX_RING_MASK;
  uint32_t chunk = USB_TX_RING_SIZE - idx;     /* contiguous up to buffer end */
  if (chunk > used)             chunk = used;
  if (chunk > USB_TX_CHUNK_MAX) chunk = USB_TX_CHUNK_MAX;

  if (CDC_Transmit_FS(&tx_ring[idx], (uint16_t)chunk) == USBD_OK)
  {
    tx_inflight = chunk;
  }
}

uint8_t usb_ready(void)
{
  return hUsbDeviceFS.dev_state == USBD_STATE_CONFIGURED;
}

/* Queue bytes. All-or-nothing: returns len, or 0 if not enough space. */
uint32_t usb_write(const uint8_t *data, uint32_t len)
{
  uint32_t free = USB_TX_RING_SIZE - (tx_head - tx_tail);
  if (len == 0) return 0;
  if (len > free)
  {
    tx_dropped += len;
    return 0;
  }

  uint32_t head  = tx_head;
  uint32_t idx   = head & USB_TX_RING_MASK;
  uint32_t first = USB_TX_RING_SIZE - idx;     /* space before wrap */
  if (first > len) first = len;
  memcpy(&tx_ring[idx], data, first);
  memcpy(&tx_ring[0], data + first, len - first);

  __DMB();                  /* data must be in ring before head moves */
  tx_head = head + len;

  NVIC_DisableIRQ(OTG_FS_IRQn);   /* stop TransmitCplt racing this kick */
  usb_tx_kick();
  NVIC_EnableIRQ(OTG_FS_IRQn);
  return len;
}

int usb_printf(const char *fmt, ...)
{
  static char buf[256];
  va_list ap;
  va_start(ap, fmt);
  int n = vsnprintf(buf, sizeof(buf), fmt, ap);
  va_end(ap);
  if (n <= 0) return n;
  if (n > (int)sizeof(buf) - 1) n = sizeof(buf) - 1;
  return usb_write((const uint8_t *)buf, (uint32_t)n) ? n : -1;
}

uint32_t usb_tx_dropped(void) { return tx_dropped; }
uint32_t usb_tx_free(void)    { return USB_TX_RING_SIZE - (tx_head - tx_tail); }
```

### Why the tricky lines are there
- **`__DMB()` before `tx_head = ...`:** `tx_ring` is not `volatile`, so the compiler may move the `memcpy` stores after the `head` update. The USB interrupt could then send bytes that are not written yet. `__DMB()` prevents this.
- **Masking `OTG_FS_IRQn` around the kick in `usb_write`:** without it, the main loop and `TransmitCplt` could both see `tx_inflight == 0` and start two transfers. Only the USB IRQ is masked, so SysTick keeps running.
- **`tx_inflight = 0` in Init and DeInit:** if the cable is pulled during a transfer, `TransmitCplt` never comes and USB would stop sending for good. `tail` is not moved, so the unsent chunk is sent again after reconnecting.
- Data queued before the PC connects stays in the ring and goes out on the next `usb_write`.
- `usb_ready()` now means "a host is connected", not "not busy".

USB API (`usbd_cdc_if.h`):

| Function | What it does |
|---|---|
| `usb_ready()` | 1 if the PC has enumerated the board (CONFIGURED) |
| `usb_write(data, len)` | Queues bytes. Returns `len`, or 0 if the ring is full (the message is dropped). Never blocks. |
| `usb_printf(fmt, ...)` | Formats up to 255 characters and queues them. Returns -1 if dropped. Supports `%f`. |
| `usb_read(dst, max)` | Copies the last received packet (up to 64 B). Returns 0 if nothing is waiting. |
| `usb_tx_dropped()` | Total bytes dropped so far |
| `usb_tx_free()` | Free bytes in the TX ring |

## Rules to remember

- **Never use `printf` again.** USART3 and `__io_putchar` are gone, so `printf` jumps to address 0 and HardFaults. Use `usb_printf`.
- Do not send USB data from inside an interrupt. The receive callback only copies and sets a flag, and the main loop sends.
- A crash during boot, before the PC enumerates, now gives no text output. Use the CubeIDE debugger, or the red LED (LD3) in `Error_Handler`.
- Keep `-u _printf_float` in `CMakeLists.txt`.
- Commit before every CubeMX regenerate (done each time today).
- CN1 = ST-Link (power, flashing, COM26). CN13 = our USB CDC (COM41).

## Next steps

**Plan for 2026-11-26: set up the folder layout.**

```
sensor_fusion/
├── Core/, USB_DEVICE/, Drivers/, Middlewares/   ← CubeMX owns these
├── App/          ← your code that talks to hardware (calls HAL)
├── Lib/          ← your pure logic (no HAL, no registers)
└── test/host/    ← PC unit tests for Lib/ (MinGW gcc)
```

- **CubeMX folders:** regenerated on every Generate. Keep only small glue there, for example `main.c` calls `app_init()` / `app_loop()`.
- **`App/`:** code that must run on the STM32 (HAL, I2C/SPI, USB, timers). Examples: `App/imu.c` (sensor driver), `App/app.c` (main loop body).
- **`Lib/`:** only math and data handling, with no `stm32f7xx_hal.h`. The same `.c` compiles for both the STM32 and the PC. Examples: `Lib/ringbuf.c`, `Lib/fusion.c` (complementary, Madgwick or Kalman filter), `Lib/filter.c`, `Lib/parser.c` (PC commands).
- **`test/host/`:** small PC programs that check `Lib/` with fixed inputs and expected outputs. They run in seconds, with no flashing and no board.

Why: fusion math bugs are found quickly with known inputs, ring buffer edge cases (wrap, exactly full) are easy to force, CubeMX regenerates cannot touch your code, and `Lib/` stays the same if the MCU or sensor changes. The 5 kg project (`F:\5kg_v2_firmware`) used the same idea.
