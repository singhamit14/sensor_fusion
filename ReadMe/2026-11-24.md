Steps to create the project in CubeMX:

2. **System Core > SYS**: Debug = **Serial Wire** (PA13/PA14).
3. **System Core > RCC**: High Speed Clock (HSE) = **BYPASS Clock Source**, because the ST-Link supplies an 8 MHz clock on MCO.

5. **System Core > CORTEX_M7**: **ICache = Enabled**. Leave **DCache off** until DMA cache handling is in place.

7. **Project Manager > Project**: Name = `sensor_fusion`, Location = `F:\`, Toolchain / IDE = **CMake**.
8. **Project Manager > Code Generator**: tick "Generate peripheral initialization as a pair of '.c/.h' files per peripheral".

## Step 7: printf over USART3

`syscalls.c` already has a weak `_write()` that calls `__io_putchar()` for each character, so only `__io_putchar()` had to be written.

**`Core/Src/usart.c`**, in `/* USER CODE BEGIN 1 */`:

```c
int __io_putchar(int ch)
{
  if (ch == '\n')
  {
    uint8_t cr = '\r';
    HAL_UART_Transmit(&huart3, &cr, 1, HAL_MAX_DELAY);
  }
  uint8_t c = (uint8_t)ch;
  HAL_UART_Transmit(&huart3, &c, 1, HAL_MAX_DELAY);
  return ch;
}
```

**`Core/Src/main.c`**:
- `/* USER CODE BEGIN Includes */`: `#include <stdio.h>`
- `/* USER CODE BEGIN 2 */`:
  ```c
  setvbuf(stdout, NULL, _IONBF, 0);   /* no buffering: text appears immediately */
  printf("\nsensor_fusion boot, SYSCLK = %lu Hz\n", HAL_RCC_GetSysClockFreq());
  ```

Viewing the output: Device Manager shows "STMicroelectronics STLink Virtual COM Port (COMx)". In PuTTY, open Serial on that `COMx` at 115200.

**Result: printf works.** The boot line shows `SYSCLK = 216000000 Hz`.

## Step 8: Turn on `%f` in printf

`nano.specs` leaves out float formatting by default, so `%f` printed nothing.

The generated `CMakeLists.txt` has **no** `target_link_options` section, so it was added by hand at the end of the file, after `target_link_libraries(...)`:

```cmake
# Enable float support in printf (nano.specs drops it by default)
target_link_options(${CMAKE_PROJECT_NAME} PRIVATE
    -u _printf_float
)
```

Check: `cmake --preset Debug` configured with no errors, and `-u _printf_float` appears in the link command in `build\Debug\build.ninja`.

**Build error found while testing:**

```
main.c:114:35: error: 'n' undeclared (first use in this function)
```

Cause: the line `static uint32_t n = 0;` had been commented out, but `n++` was still used. The fixed USER CODE 3 block:

```c
static uint32_t n = 0;
HAL_GPIO_TogglePin(LD1_GPIO_Port, LD1_Pin);
printf("tick %lu  ms=%lu  pi=%.3f\n", n++, HAL_GetTick(), 3.14159f);
HAL_Delay(500);
```

**Result: float printf works** (`pi=3.142`). This adds about 10 KB of flash.

## Quick reference

```powershell
# configure (once, or after a CubeMX regenerate or a CMakeLists.txt change)
cmake --preset Debug

# build
cmake --build --preset Debug

# flash
STM32_Programmer_CLI -c port=SWD -w build\Debug\sensor_fusion.elf -v -rst

# clean rebuild
Remove-Item -Recurse -Force build; cmake --preset Debug; cmake --build --preset Debug
```

## Rules to remember

- Edit generated files only inside `/* USER CODE BEGIN ... */` / `/* USER CODE END ... */` blocks. Anything outside them is lost on regenerate.
- `CMakeLists.txt` at the root is yours and CubeMX does not overwrite it. CubeMX owns `cmake/stm32cubemx/CMakeLists.txt`.
- **Commit before every CubeMX regenerate**, so `git diff` shows what it changed.
- printf is blocking (about 87 µs per character at 115200). Do not use it in ISRs or fast loops. Later, use DMA or interrupt-driven TX with a ring buffer.
- **F7 trap, D-cache + DMA:** DMA buffers need `SCB_CleanDCache_by_Addr` / `SCB_InvalidateDCache_by_Addr`, or an MPU region marked non-cacheable. DCache is still **off**.
- **F7 trap, flash sectors:** flash is erased in 32/128/256 KB sectors. To store a config record, reserve a sector in the linker script.
